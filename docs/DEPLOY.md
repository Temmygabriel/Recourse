# Recourse — Deploy Runbook

How to get a working deployment from a clean clone. Every command here has been
run, except where marked otherwise.

**Testnet only.** Base Sepolia and GenLayer Bradbury. No real funds.

---

## 0. The ordering constraint

**The GenLayer contract deploys first. Always.**

`RecourseEscrow` takes `sourceContract_` and `sourceChainId_` in its
**constructor**, and neither has a setter — unlike `relayer`, which the owner
can rotate. The escrow is permanently bound to one judgment contract on one
chain, fixed at deploy time.

So the sequence is forced:

```
1. Deploy RecourseJudgment on GenLayer   → get its address
2. Deploy RecourseEscrow on Base Sepolia → pass that address + chain id
3. Point the relayer at both
4. Point the frontend at the escrow
```

Getting this backwards means redeploying the escrow. There is no migration path
and no upgrade proxy.

## 2. Deploy the judgment contract (GenLayer)

```bash
genlayer network set testnet-bradbury
genlayer deploy --contract genlayer/contracts/recourse_judgment.py
```

Record the deployed address. **Verify it is actually finalized before
continuing** — a `deploy` that prints an address is not proof:

```bash
genlayer receipt <txHash>
```

### ⚠️ Known blocker — read before retrying

As of 2026-09-11 this deploy **has not succeeded.** Two separate faults, both
measured rather than guessed:

1. **A stranded transaction holds the account nonce.** An earlier attempt
   (`0x139c9ed1…823e`) sits unmined at nonce 284 having bid **0.1732 gwei**,
   while the network price is **0.1568 gwei**. The CLI has **no gas-price flag**
   — `deploy` accepts only `--contract`, `--rpc`, `--args` — so every retry bids
   the current network price and is rejected:
   `insufficient gas price to replace existing transaction`.
   **Retrying cannot succeed while the network price is below 0.1732 gwei.**
2. **The RPC disagrees with itself.** `rpc-bradbury.genlayer.com` load-balances
   across nodes with unsynchronised mempools. Polling one hash three times
   returned `null`, `null`, `FOUND`. Pool membership has no single answer here.

Ways out, in order of preference:

- **Wait** for the network gas price to rise above 0.1732 gwei, then retry. The
  stranded tx may also simply be mined, in which case read its receipt — the
  contract is already deployed.
- **Use a fresh GenLayer account.** A stranded nonce does not follow a new
  account. Create one with `genlayer account`, then fund it from a faucet.
- **Replace the tx at nonce 284** with a higher bid. This needs the keystore
  password (`~/.genlayer/keystores/default.json` is scrypt-encrypted), so only
  the key's owner can do it.

### Contract size limit

Bradbury rejects deploys whose **compiled artifact** exceeds roughly
**39,869 B**. The source is 21,296 B; the artifact size has not been measured.
If it lands near the cap, minify mechanically into a separate deploy artifact —
see `docs/MONEY_RAILS_AUDIT.md` (Issue 4) for the approach. Do **not** treat a
successful StudioNet deploy as evidence it will fit on Bradbury.

## 3. Deploy the escrow (Base Sepolia)

Constructor:

```solidity
constructor(
    IERC20 usdc_,
    uint256 sourceChainId_,
    address sourceContract_,
    address relayer_,
    uint16  disputeBondBps_,
    address owner_
)
```

- `usdc_` — `0x036CbD53842c5426634e7929541eC2318f3dCF7e` (Base Sepolia USDC, 6 dp)
- `sourceChainId_` — the GenLayer chain id from step 2
- `sourceContract_` — the judgment contract address from step 2
- `relayer_` — `0x49B4f09C5894c1C90B0ca9099AF3De0Faf7f3037`
- `disputeBondBps_` — between `100` and `2000` (1%–20%); the contract reverts outside that range
- `owner_` — `0xe5Fe9119000C9E1113dc504891A83Da7bbaa7a7b`

```bash
forge create contracts/src/RecourseEscrow.sol:RecourseEscrow \
  --rpc-url "$BASE_RPC_URL" \
  --private-key "$(jq -r .privateKey .secrets/deployer.json)" \
  --constructor-args \
    0x036CbD53842c5426634e7929541eC2318f3dCF7e \
    <GENLAYER_CHAIN_ID> \
    <GENLAYER_CONTRACT_ADDRESS> \
    0x49B4f09C5894c1C90B0ca9099AF3De0Faf7f3037 \
    500 \
    0xe5Fe9119000C9E1113dc504891A83Da7bbaa7a7b
```

> `--private-key` puts the key on the command line, where it lands in shell
> history and the process table. Prefer `--keystore` or a hardware wallet if you
> have one. For the hackathon demo, a throwaway shell is the mitigation.

Expected size: **16,403 B runtime**, comfortably under the 24,576 B EIP-170
limit.

Verify what you deployed:

```bash
cast call <ESCROW> "sourceContract()(address)" --rpc-url "$BASE_RPC_URL"
cast call <ESCROW> "sourceChainId()(uint256)"  --rpc-url "$BASE_RPC_URL"
cast call <ESCROW> "relayer()(address)"        --rpc-url "$BASE_RPC_URL"
```

All three must match what you intended. **These cannot be changed later.**

## 4. Run the relayer

```bash
cd relayer
cp .env.example .env      # then fill it in
npm install
npm run build
DRY_RUN=true node --env-file=.env dist/index.js
```

**Start with `DRY_RUN=true`.** It signs and simulates every decision but never
broadcasts, so it exercises the whole pipeline — including the escrow's own
signature recovery — without moving money. Run at least one full dispute
through it before turning `DRY_RUN` off.

The relayer checks at startup that its configured `GENLAYER_CHAIN` agrees with
the escrow's immutable `sourceChainId`, and refuses to run if they disagree.
That check exists because a mismatch would produce decisions the escrow silently
rejects.

State lives in `.relayer-state.json` (gitignored) so a restart resumes rather
than re-spending fees.

## 5. Point the frontend at the escrow

Local:

```bash
cd frontend
cp .env.example .env.local
# set NEXT_PUBLIC_ESCROW_ADDRESS to the escrow from step 3
npm run dev
```

### Vercel

`frontend/` is Vercel-ready — it builds clean (`next build` exit 0, nine routes)
against the locked dependencies. Set in **Project Settings → Environment
Variables**, for **Production, Preview and Development** alike:

| Variable | Value |
|:--|:--|
| `NEXT_PUBLIC_ESCROW_ADDRESS` | the escrow address from step 3 |
| `NEXT_PUBLIC_BASE_SEPOLIA_RPC_URL` | optional; a keyed RPC if the public one rate-limits |

`NEXT_PUBLIC_ESCROW_ADDRESS` is baked into the client bundle at build time, so
changing it requires a redeploy. A missing value is a **build-time error**, not
a blank page — that is deliberate.

**Do not deploy to Vercel before step 3 completes.** The build will succeed, but
every route will render its empty state, because there is no escrow to read
from. A live URL showing nothing is worse evidence than no URL.

## 6. Seed the demo

With the deployer or demo wallet, post two or three offers through the UI at
`/offers/new`. Then walk one through to settlement so the home page's proof card
has a real result to show — the card renders a real `Settled` event or nothing
at all; it never shows a placeholder.

Sequence for a settled demo:

1. **Post** an offer as the seller.
2. **Pay** as a different wallet (a seller cannot buy their own offer).
3. **Mark delivered** as the seller.
4. **Dispute** a requirement as the buyer, posting the bond.
5. Let the relayer carry the judgment, or call `settle()` directly.

## 7. Post-deploy checklist

- [ ] `genlayer receipt <txHash>` shows the judgment contract **finalized** (not just accepted)
- [ ] `sourceContract()` and `sourceChainId()` on the escrow match the judgment contract
- [ ] `relayer()` on the escrow matches `relayer.json`
- [ ] **Escrow reconciles** — `cast call <escrow> "totalHeld()(uint256)"` equals
      `cast call <usdc> "balanceOf(address)(uint256)" <escrow>` at every point in
      the demo, not just at rest. Run it once mid-dispute, when the escrow holds
      both a price and a bond; that is the state where a leak would show.
- [ ] Relayer runs clean in `DRY_RUN=true` for one full dispute
- [ ] At least one purchase settled, visible at `/verdict/<id>` and `/receipt/<id>`
- [ ] Home page proof card shows the real settlement
- [ ] No key material in `git ls-files`

The reconciliation check is the one item here that nothing else covers. It is a
plain read, it needs no key, and it is the only way a retained-value bug in the
escrow becomes visible — if the two numbers ever diverge, stop and find out why
before showing the demo.
